# `@stylos/ui`

The Svelte 5 component package, built to SPEC 0009 against the contracts in [`docs/components/registry/`](../../docs/components/registry/). The stack and the layering are ADR 0002; the version is the system's, in lockstep ([`ARCHITECTURE.md`](../../ARCHITECTURE.md) §9).

## The layers, top is thinnest

1. **`dist/tokens.css`** — the custom properties, generated by `npm run tokens:css` (SPEC 0007). Nothing below restates a value.
2. **Per-component CSS** (`src/components/<name>/<name>.css`) — selectors keyed on data attributes carrying the contract's values. Every value is a `var(--stylos-…)`; a hex or a raw `px` outside `tokens.css` fails Stylelint (`npm run lint:css` at the root).
3. **Behaviour** (`src/behaviors/`, when a component needs one) — framework-free, operating on elements.
4. **`.svelte` wrapper** — takes the contract's props, writes the data attributes the CSS reads. The only Svelte-specific file; layers 1–3 survive a framework change.

## Generated, never hand-written

- `src/components/<name>/props.ts` — from the entry's `api` by `tools/build-ui-types.mjs`, so props ↔ `api` is checked by the compiler.
- `dist/` — `tokens.css` + `tokens.json` (`tokens:css`) and `package/` (`svelte-package`).

`npm run ui:generate` at the root rebuilds all of it; `npm run ui:build` builds the package (generation runs as its `prebuild`).

## Name conversion

The registry holds the public contract; the generator converts its property names for Svelte under FND-NAMING-05 ([naming.md](../../docs/foundations/naming.md)).

- Component exports use PascalCase: `Icon Button` → `IconButton`, `Indicator Status` → `IndicatorStatus`.
- Names become camelCase: `label text` → `labelText`, `is required` → `isRequired`. The generator removes punctuation within each word before joining the words: `is read-only` → `isReadonly`.
- When the contract has exactly one slot, its prop is `children`, following Svelte's convention for child content. With several slots, each prop uses the camelCase form of its contract name.
- Variant values are copied unchanged. For example, `extra small` remains `"extra small"`.

Both `kind: text` (textual content) and `kind: string` (a non-text string value such as an icon identifier) generate TypeScript `string`. The distinction remains in the registry; `Icon.name` stays the `name` prop.

These conversions are implemented in `tools/build-ui-types.mjs`; they change spelling, not the property's meaning.

## Typography exports

The global contract is [Typography](../../docs/foundations/typography.md). `npm run ui:generate` projects the recorded styles in [`figma/text-styles.yaml`](../../figma/text-styles.yaml) to `dist/text.css`, with one class per style: `text/base/medium` becomes `.stylos-text-base-medium`, and `heading/h2` becomes `.stylos-heading-h2`. Link the token and font exports alongside the text stylesheet.

A style's paragraph spacing is exposed as `--stylos-paragraph-spacing`. The stylesheet does not add paragraph margins automatically; the consumer applies this property to its paragraph layout. Case metadata becomes `text-transform`; width metadata is projected only for non-heading styles.

A theme replacing the family tokens supplies its own compatible font faces. Weight values remain shared role tokens under FND-TYPOGRAPHY-05; font substitution does not introduce arbitrary component weights.

### Content typography

FND-TYPOGRAPHY-10 defines the boundary between content styles and component token use. For individual pieces of content, apply a complete class from `text.css`. For headings and paragraphs rendered from Markdown, import `@stylos/ui/prose.css` alongside tokens and fonts:

```js
import "@stylos/ui/tokens.css";
import "@stylos/ui/fonts.css";
import "@stylos/ui/prose.css";
```

```html
<article class="stylos-prose">
  <h1>Project settings</h1>
  <p>Change the name and description of your project.</p>
  <h2>Members</h2>
  <p>Review access to the project.</p>
</article>
```

The body defaults to the complete `text/base/medium` style. `data-text-style` selects one of the recorded `text/base/*` or `text/emphasis/*` styles across the five sizes; for example, `<article class="stylos-prose" data-text-style="text/base/small">`. An absent or unsupported value retains the medium default. Headings `h1`–`h6` use their corresponding `heading/h1`–`heading/h6` styles, independently of body size.

`tools/build-prose-css.mjs` uses the same text-style declaration projection as `text.css` and adds the approved document margins under FND-TYPOGRAPHY-11, FND-TYPOGRAPHY-12 and FND-TYPOGRAPHY-13. Missing, incomplete or unresolved required styles stop generation. Paragraph margins use the selected body's `--stylos-paragraph-spacing`; heading margins reference semantic gap tokens. The export requires tokens and fonts, but no framework, text wrappers or Markdown parser. Tables, quotations, links and code blocks still require their own approved design contracts.

The workshop's `Foundations/Typography` stories show the recorded text styles, headings and paragraphs, the five base body sizes, and spacing cases with adjacent and wrapping headings. Their interaction checks measure rendered block distances and document boundaries.

The [approved Figma spacing reference](../../figma/typography.md#document-spacing-reference) is implemented with logical block margins on headings and paragraphs. Keep these blocks in normal block flow inside the document container so adjacent margins collapse. Flex or grid on a parent outside `.stylos-prose` does not change its internal block flow; making the document container itself flex or grid requires a layout that calculates the single adjacent gap under FND-TYPOGRAPHY-12. Boundary resets apply to direct heading and paragraph children of `.stylos-prose`.

### Heading width

Heading styles follow FND-TYPOGRAPHY-09. For `heading/*`, the CSS generator omits `font-stretch`, including when an older style record contains width metadata. The selected typeface renders at its normal width.

## Adding a component

Storybook groups components by their Figma pages. Add page membership in
`apps/workshop/component-groups.json` when introducing a component. Authored
examples share the generated component title and explicit meta ID; keep the
existing ID when changing its group so saved links continue to work.

Per SPEC 0009 §5, contract first: the entry's `api` is corrected to describe the web component in the same session the `.svelte` is written. Then a directory under `src/components/` named by the entry's slug, the authored CSS and wrapper, an export in `src/index.ts` — and the generators produce the props type and the workshop story.

## Accessibility implementation and verification

### Input Text

`InputText` uses a native, single-line text input and the existing `Label`.
The consumer sets its width through the surrounding layout.
The native input covers the complete field, including the areas under its
decorative icons and suffix. Those elements use `pointer-events: none`.
The framework-free `inputTextBehavior` measures the decorative groups and
reserves their actual widths in the input's text padding; the Svelte wrapper
attaches it automatically. Consumers of the independent HTML/CSS export
import it from `@stylos/ui/behaviors/input-text`, attach it to
`.stylos-input-text-field` and call its `destroy` method on removal.

```svelte
<script>
  let reference = $state("");
</script>

<InputText name="reference" labelText="Reference" bind:value={reference}
  hasAdditionalText additionalText="Use the invoice reference" isRequired />
```

`value` determines filledness. `state` accepts `default`, `read only` and
`disabled`; hover and focus are browser states. Validation is supplied by the
consumer: error sets `aria-invalid`, error and warning show the associated
supporting line, and success shows the mark. Read-only and disabled suppress
validation. With `hasLabel={false}`, provide an external associated label,
`labelIds`, or `accessibleName`. Supporting text and the optional suffix are
combined with `descriptionIds` in the input's accessible description.

Pointer and keyboard focus use `--stylos-focus-base`, the composite Figma
effect-style token. Its halo replaces the resting shadow on the entire native input.

The icon snippets are decorative; no placeholder icon is substituted and
they are not action slots. Storybook offers Default followed by Icons
playground with the complete active icon set. Vertical trim stays off,
matching all 140 Figma variants. `Label.htmlFor` and `additionalTextId`
provide native associations without changing Label's CSS.

### Button Icon

`ButtonIcon` renders an icon-only native button with `variant="base" | "outline" | "ghost"`.
It defaults to base/primary/medium and supports the same five tones and target
heights as Button. Targets are square: 24/32/40/48/56 units with centred
16/20/24/28/32-unit icons. The icon has no optical overhang.

```svelte
{#snippet addIcon()}<Icon name="add" />{/snippet}
<ButtonIcon icon={addIcon} accessibleName="Add item" onclick={addItem} />
<ButtonIcon variant="outline" icon={addIcon} accessibleName="Add item" />
<ButtonIcon variant="ghost" icon={addIcon} accessibleName="Add item" state="disabled" />
```

Supply a configured icon snippet and a non-empty `accessibleName` describing the
action. The component supplies no default icon or action name. The icon is
hidden from assistive technology; compose a surrounding Tooltip when the action
needs a visible explanation. Default and Icons playground use add/Add item as
sample content, and the playground can select any icon in the active set.

Native hover, press, keyboard focus, disabled fieldsets and form properties work
as in Button. `type="button"` is the default; submit/reset, `id`, `name`, `value`,
`form`, `descriptionIds` and `onclick` retain their native meanings. Button CSS
supplies surfaces, inside borders, shadows, focus and micro/linear Motion, with
immediate changes under reduced motion. The footprint supports the recorded size
presets; external dimension overrides are not part of this contract.

Independent HTML uses `.stylos-button-icon` plus `.stylos-button-base`,
`.stylos-button-outline` or `.stylos-button-ghost`, with the same data attributes
as Button and a decorative `.stylos-button-icon-mark` child. Link tokens, fonts
and `@stylos/ui/css/button-icon.css`; this export includes its Button dependency.

### Surface profiles

The web implementation represents the level and attachment from FND-LAYERS-01
and FND-LAYERS-02 with component-owned DOM attributes:

- `data-surface-layer`: `0` through `6`.
- `data-surface-attachment`: `in-layout`, `control`, `free` or `window-edge`.
- `data-surface-edge`: `top`, `right`, `bottom` or `left` for edge panels.

Shared `behaviors/surface.css` selects elevation and appearance motion under
FND-LAYERS-04:

| Surface | Level | Attachment |
| --- | --- | --- |
| Button / Button Icon: Base, Outline | 1 | `in-layout` |
| Button / Button Icon: Ghost | 0 | `in-layout` |
| Input Text / Select field | 1 | `in-layout` |
| Tooltip | 2 | `control` |
| Dropdown | 3 | `control` |

The component uses `--_stylos-surface-shadow` when composing its effects.
Inside strokes, focus and disabled effects remain component state treatments.
Each declared surface resets its private profile so nested surfaces do not
inherit their owner's elevation or motion. `behaviors/surface-motion.ts` reads
the shared transforms and timing; it preserves interrupted motion and can put
its visibility marker on a separate floating positioner. `window-edge` profiles require a
`data-surface-edge` side and translate by the panel extent without scaling.
A free or control-attached level-5 surface uses its general shift/scale profile;
edge attachment selects edge travel instead. This supplies shared mechanics for future panels; Modal and Drawer are not
implemented here. Runtime stacking still needs the owner-aware overlay manager.

Svelte supplies the declarations; framework-free/static markup must carry the
same `data-surface-layer` and `data-surface-attachment` attributes. Independent
component styles include the shared sheet. These attributes are internal
component decisions, not extra consumer props or styling overrides.

### Dropdown: single-value selection

`Dropdown` supplies the panel and `DropdownItemDefault` supplies a plain option.
The panel has no built-in trigger. `dropdownBehavior` connects an external
button to a plain single-choice panel using Zag Select; value state stays with
the owner. This is the first Dropdown slice, chosen before action menus.
Interaction follows [Zag Select](https://zagjs.com/components/react/select) and
[APG listbox guidance](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/), with an
explicit Tab-dismissal adapter for the portaled single-choice composition.

```svelte
<script lang="ts">
  import { Button, Dropdown, DropdownItemDefault, dropdownBehavior } from "@stylos/ui";
  let value = $state("design");
  const id = $props.id();
  const options = [
    { value: "design", label: "Design" },
    { value: "development", label: "Development" },
  ];
  const selectedLabel = $derived(options.find(option => option.value === value)?.label ?? "Choose");
</script>

<div use:dropdownBehavior={{ id, value, accessibleName: "Workspace",
  onValueChange: next => { value = next; } }}>
  <span data-dropdown-trigger><Button labelText={selectedLabel} /></span>
  <div data-dropdown-positioner hidden>
    <Dropdown accessibleName="Workspace">
      {#snippet contentSlot()}
        {#each options as option (option.value)}
          <DropdownItemDefault value={option.value} labelText={option.label}
            isSelected={option.value === value ? "true" : "false"} />
        {/each}
      {/snippet}
    </Dropdown>
  </div>
</div>
```

Supply a non-empty accessible name and unique non-empty option values. Rows
inherit the panel size; configure the external trigger to match that size. The adapter portals the panel into its
document, matches the trigger width and places it below by default; `placement`
also accepts `bottom-end`, `top-start` and `top-end`. `disabled` disables the
whole trigger; row `state="disabled"` makes that option unavailable. It observes
changed option labels, values, availability and content. Destroying the adapter
removes its listeners and observer and returns the panel to its owner.

Arrow keys, Home/End and typeahead move the highlighted option. Enter/Space or
click selects and closes; Escape closes without selecting and returns focus.
Tab dismisses and continues through the page. The panel is not a focus trap.
The popup follows [FND-MOTION-19](../../docs/foundations/motion.md#fnd-motion-19--surface-entry-selects-a-fixed-profile-by-level)
through the shared surface-motion adapter and stylesheet at Layers level 3. Closing immediately
sets `inert` and `aria-hidden` on the positioner; focus and selection do not wait
for the animation.

Selection uses `listbox`/`option` and `aria-selected`; the trigger uses Zag's
select-only `combobox` semantics. Dropdown itself is not a form field and does
not submit a value; Select supplies form integration.

`backSlot`, `searchSlot` and `actionsSlot` retain the Figma bands and accept
configured content. Navigation below uses the Back band; search and staged
selection require their own behaviour. The current `dropdownBehavior` rejects those
bands. The normal single-choice example contains only `contentSlot`. A panel's
default maximum is derived from its six-and-a-half-row profile; `maxHeight`
accepts an owner-supplied CSS length. Overflow uses the Figma small/absolute treatment on the native scrollbar. Text has no Vertical trim, as in Figma.

Independent CSS exports are `@stylos/ui/css/dropdown.css` and
`@stylos/ui/css/dropdown-item-default.css`; framework-free behaviour is also
exported as `@stylos/ui/behaviors/dropdown`. Static previews carry option and
selection semantics without running behaviour. Storybook has one Default
selection example and an Icons playground after the row's Default.

Verification covers the five size profiles, pointer and keyboard selection,
disabled skipping, typeahead, Escape, Tab dismissal, overflow and focus return
in the workshop's Chromium browser. Screen-reader assessment remains part of
the package's verification plan. Recorded Figma colour-pairing findings remain
in the registry; this implementation does not change the palette.

### Dropdown: Checkbox and Toggle rows

`DropdownItemCheckbox` and `DropdownItemToggle` compose the existing native
controls and inherit `Dropdown` size. Bind `isSelected` to `"false" | "true"`.
The complete row is a label; keyboard focus surrounds the row once. Optional
additional text is an associated description. Toggle accepts `alignment="start|end"`.

Render these rows inside `Dropdown contentRole="group"` and connect an external
button and `[data-dropdown-positioner]` using `dropdownControlsBehavior`:

```svelte
<div use:dropdownControlsBehavior={{ id: "notifications", accessibleName: "Notifications" }}>
  <span data-dropdown-trigger><Button labelText="Notifications" /></span>
  <div data-dropdown-positioner hidden>
    <Dropdown contentRole="group" accessibleName="Notifications">
      {#snippet contentSlot()}
        <DropdownItemToggle labelText="Email" bind:isSelected={emailEnabled} />
      {/snippet}
    </Dropdown>
  </div>
</div>
```

The non-modal popup stays open after changes. Zag Popover handles placement,
Escape, outside dismissal, focus return and portalled Tab order. Native controls
handle Space, state, disabled rows and form reset. Checkbox values are collected
by the owner; Toggle changes take effect immediately in that owner's handler.
Use `form` explicitly when a control must submit to a form outside the body portal.
The adapter supports plain groups only; search, nesting within control groups
and Apply/Cancel require separate behaviour. Single-choice `dropdownBehavior` remains listbox-only.

Independent CSS is `@stylos/ui/css/dropdown-item-checkbox.css` and
`@stylos/ui/css/dropdown-item-toggle.css`. The framework-free popup adapter is
also exported at `@stylos/ui/behaviors/dropdown-controls`.

### Dropdown: Parent and navigation

`DropdownItemParent` is a native button with the shared row treatment and a
fixed `arrow_right`. `controls` identifies the next panel; it never selects a
value. `DropdownItemDefault interaction="action"` provides a native button for
leaves and the Figma Back band. The default `interaction="option"` retains the
existing Select/listbox contract.

`dropdownNavigationBehavior` connects an external button and
`[data-dropdown-positioner]` to a `[data-dropdown-navigation]` wrapper. Inside
that wrapper, mount named `[data-dropdown-panel]` sections with unique IDs;
the first is the root. Each section contains a named `Dropdown contentRole="group"`.
Parent `controls` points to one of those section IDs. Leaves use action-mode
Default rows with unique, non-empty values. Render the Back action in each
non-root panel's `backSlot`, with an empty value and a leading `arrow_back`.
The level graph and authored rows stay stable while the adapter is mounted;
remount it to replace that graph.

Supply `{ id, accessibleName, value, onValueChange }`, optional `disabled` and
the existing four `placement` values. The owner retains the selected value.
Zag Popover supplies a non-modal dialog, placement, dismissal, focus return and
portalled Tab order. Parent replaces the visible level in that same popup;
Back restores the originating row and its list's scroll position. Only a leaf
calls `onValueChange` and closes. Reopening starts at the root.

Native buttons handle Enter, Space and Tab. Arrow Up/Down, Home/End and typeahead
move between available rows; Arrow Right enters Parent and Arrow Left returns.
Disabled rows are skipped. Escape dismisses without selecting. The existing
layer-3 entry/exit runs only when the popup opens or closes. Internal levels
use slide-out followed immediately by slide-in across the panel’s own width,
without fading: forward exits left and arrives from the right; Back reverses it. The frame and shadow stay continuous while height interpolates.
The next level and height change begin when the outgoing level has left.
Arrival and expansion use medium/enter with enter easing; departure and
contraction use medium/exit with exit easing. Interrupted navigation continues
from its current presentation, and reduced motion switches levels immediately. Destroy returns the portal to its owner and removes
listeners and DOM changes. This composition does not supply native form data
or replace Select Cascade.

Independent CSS: `@stylos/ui/css/dropdown-item-parent.css`. The adapter is also
exported as `@stylos/ui/behaviors/dropdown-navigation`. Storybook adds Parent
Default followed by Icons playground, and Dropdown's compact Nested navigation
example. Static previews preserve native Parent/action button semantics.

### Native scrollbar styling

`@stylos/ui/scrollbar.css` styles an existing overflow element with the
`stylos-scrollbar` class. `data-scrollbar-size="small"` selects the 4 px drawing
instead of the default medium 8 px drawing. `data-scrollbar-position="absolute"`
selects the transparent track and narrower resting thumb; this describes the
Figma treatment and does not set CSS positioning. Dropdown uses small/absolute
at every panel size, matching its Figma instance.

Chromium and WebKit use token-based widths, insets, rounded thumbs and native
thumb hover/active colours. Horizontal scrolling uses the same rotated geometry.
Other browsers use standard `scrollbar-width: thin` and token colours. The
browser still owns overflow, thumb length, wheel, touch, keyboard and dragging;
no drawing-only `state`, visibility or disabled prop is added. Forced colours
restore browser styling. This is CSS styling, not a separately rendered Svelte
Scrollbar or a ScrollArea.

Browser differences are intentional: the native gutter may occupy layout space
instead of overlaying content, and Firefox chooses the thickness and individual
thumb states. The Figma illustration's fixed thumb length is not imposed on
real content. See [Chrome's scrollbar styling guide](https://developer.chrome.com/docs/css-ui/scrollbar-styling)
for the native CSS limitations. The independent Dropdown stylesheet includes
these rules; importing the standalone scrollbar stylesheet is only needed for
other scroll containers. Chromium verification covers the 4 px gutter, 1 px
resting thumb, native dragging, wheel scrolling, keyboard scrolling and no
gutter when content fits. The fallback has not been visually tested in Firefox.

### Link

`Link` renders a native anchor in two tones and five sizes, defaulting to medium.
Supply the destination through `href`; hover, active and keyboard focus are browser states.

```svelte
<Link href="/account" labelText="Open account" />

{#snippet arrow()}<Icon name="arrow_forward" />{/snippet}
<Link href="/account" labelText="Open account" hasTrailingIcon trailingIcon={arrow} />
```

`state="disabled"` removes the destination and tab stop while retaining disabled link semantics.
Optional `leadingIcon` and `trailingIcon` accept snippets containing configured components and are decorative;
show them with `hasLeadingIcon` and `hasTrailingIcon`. Their footprint follows the Link size.
Hover and focus surfaces extend outside the layout box as in Figma. Motion uses the
shared micro/linear profile and changes immediately under reduced motion.

### Checkbox Input

`CheckboxInput` renders a native checkbox with a decorative surface. Supply
`accessibleName`, or an `id` associated with a surrounding HTML label. A name
from surrounding row content remains the consumer's responsibility.

```svelte
<script>
  let selected = $state("false");
</script>

<CheckboxInput name="rows" value="42" accessibleName="Select row 42"
  size="medium" bind:isChecked={selected} />
```

Click and Space toggle the value; activating `mixed` selects `true`.
`mixed` uses the native `indeterminate` property with checked false, so it
submits no value. Checked, enabled controls submit their `name`/`value`.
`state="disabled"` and disabled fieldsets prevent activation and submission.
`form` can name an external form. `isRequired` uses native validity; associate
persistent error copy with `descriptionIds` when validation fails.

Form reset restores the selection supplied at mount, including mixed, and
updates the bound value. A cancelled reset leaves it unchanged. Hover,
pressing and focus are browser states, rather than public props. Forced
colours use the browser's native appearance. Surface colours and borders use
Motion micro/linear, with immediate changes under reduced motion. The 16 and 20 px sizes require
the target-area conditions recorded in the contract.

The workshop renders a single named checkbox in its Default playground, with Controls for its supported properties.
The exact Figma glyphs are internal masks, retaining their original sizes;
the independent CSS export embeds their SVG bytes and needs no asset folder.
The initial assistive-technology matrix below is selected; its manual results remain pending.

### Tooltip

The trigger is the single root element in the child snippet. Keep its own
accessible name and keyboard focusability; the wrapper adds no focus stop.

```svelte
<Tooltip tooltipText="Copy the link" tone="inverted">
  <button type="button" onclick={copyLink}>Copy</button>
</Tooltip>
```

The DOM behaviour uses Zag.js's vanilla adapter, independently of Svelte.
It links the trigger and text using `aria-describedby`, preserving existing
descriptions and the trigger's id and event handlers. It opens on hover and
keyboard focus, retains the surface while hovered, and closes on Escape,
blur, click and scroll. The body-level overlay avoids clipping ancestors and
appears below the trigger by default with a `gap/g-0_500` separation, and
flips or shifts at viewport edges. Do not put focusable content in the text.

Hover waits 400 ms and pointer departure has a 150 ms grace period; these
component defaults await a shared Timing decision. Keyboard focus and Escape
have no behavioural wait. Entry and exit use the same shared surface-motion
adapter as Dropdown, using its own level-2 FND-MOTION-19 profile. The trigger association updates
immediately.

For wrapping descriptions, set `type="text"` and `contentWidth` to a CSS width;
the viewport's available width limits it. A disabled native button cannot
receive keyboard focus: provide its explanation in persistent text too.

Migration from the earlier surface-only implementation: supply the described
control as Tooltip's child. Without a trigger the component renders nothing.
The independent CSS supports static tooltip surfaces; the workshop’s Default uses a live trigger.

The shared target and the boundary between component evidence and full-interface conformance are defined in [Accessibility](../../docs/foundations/accessibility.md). Implementation follows the ARIA semantics in FND-ACCESSIBILITY-02 and fulfils the registry obligations it controls; integration examples make consumer obligations visible.

Prefer a native HTML element when it supplies the required semantics and behaviour. For custom widgets, the [ARIA Authoring Practices Guide (APG)](https://www.w3.org/WAI/ARIA/apg/) supplies typical keyboard, focus and naming patterns, such as dialogs, menus and listboxes. APG is [informative guidance](https://www.w3.org/WAI/ARIA/apg/about/introduction/#apg-is-not-a-normative-standard), not another conformance standard. Use the relevant pattern as the default and document departures in the component's implementation guide. A pattern or a behaviour dependency such as Zag.js does not by itself prove accessibility.

For icons, distinguish decorative use from information and controls. Hide decoration from assistive technology; provide a text alternative for an informative icon, and an action name for an icon-only control. The name can belong to the parent control rather than the visual Icon component. See W3C's [decorative images](https://www.w3.org/WAI/tutorials/images/decorative/) and [functional images](https://www.w3.org/WAI/tutorials/images/functional/) guidance.

### Verification plan

The planned component checks combine automated assertions with manual keyboard, focus and assistive-technology checks in representative compositions. They cover supported states and consumer conditions, including accessible names, label associations and target areas. Passing axe checks alone is not a conformance assessment.

The proof interface is assessed separately for content, composition and complete user processes. Results state which uses, versions and environments were tested; they do not claim conformance for every application using the package. The work is sequenced in [PLAN.md](../../PLAN.md#42-stage-5--stylosui).

For Stage 5 acceptance, build the UI package and workshop, then run `npm run ui:verify` at the root. This derives the core membership from the plan, exhausts each component's variant product, exercises boolean properties individually, and checks generated props, built wrappers and CSS/font export paths. `npm run ui:verify:browser` serves the same cases at `http://127.0.0.1:4174`, plus representative compositions for keyboard and assistive-technology checks. Use **Run browser checks** to record light/dark DOM construction, axe on configured Default examples (with Modal/Drawer opened), and visible CSS-only samples. `npm run ui:verify:results` checks that the browser report is complete, passes and matches the source fingerprint. Detailed scope, results and remaining manual work are in the [0.2.0 acceptance record](verification/0.2.0.md).

### Checkbox Label and Checkbox Text

Both compose `CheckboxInput`, default to medium and expose the same form, selection and description properties. Visible text supplies the name; `accessibleName` may override long copy. The associated input id is generated per instance unless the consumer supplies `id`.

```svelte
<CheckboxLabel labelText="Send release notes" name="notes" bind:isChecked />
<div class="consent-column">
  <CheckboxText name="consent" isRequired bind:isChecked={consent}>
    I agree to the <a href="/privacy">privacy policy</a>.
  </CheckboxText>
</div>
```

Label hugs its single line and uses emphasis weight with string line height. Text fills the parent width, wraps using text line height and centres the box on its first line; choose the column width in the surrounding layout. Text's optional `children` snippet replaces `labelText`. Supply phrasing content such as text, emphasis and anchors, with no nested labels or additional controls. Native anchor activation follows the link without toggling selection, including inside a disabled option; a disabled checkbox does not disable an independent link. Supplementary copy belongs outside the label and is connected through `descriptionIds`; required validity does not add an error appearance.

Hover and pressing across the full label update the input's existing Motion surface transitions. Native disabled fieldsets also disable the input and copy. The CSS exports for Label/Text include the shared layout and Checkbox Input styles; link tokens and fonts separately as usual.

### Button

`Button` renders a native button with `variant="base" | "outline" | "ghost"`.
The default is base/primary/medium; all three treatments support the same five
sizes, five tones, decorative icon snippets and native form properties.

```svelte
<Button labelText="Save changes" onclick={saveChanges} />
<Button variant="outline" labelText="Cancel" onclick={cancel} />
<Button variant="ghost" labelText="Details" onclick={showDetails} />
<Button labelText="Delete" tone="danger" size="small" state="disabled" />
```

The browser derives hover, press and keyboard focus; `state="disabled"` and a
disabled fieldset prevent activation and focus. Labels are uppercased in CSS.
Surface transitions use micro/linear Motion and become immediate with reduced
motion. Optional `leadingIcon` and `trailingIcon` require their presence booleans;
unassigned icons render no slot. Marks are decorative and retain Figma's optical
alignment. `type="button"` is the default; submit/reset, `name`, `value` and `form`
retain native form behaviour. `onclick` receives the native event and can cancel
its default action. `descriptionIds` links supporting text.

Independent HTML uses `.stylos-button` plus `.stylos-button-base`,
`.stylos-button-outline` or `.stylos-button-ghost`, with `data-variant`, `data-tone`,
`data-size` and `data-state`. Link tokens, fonts and `@stylos/ui/css/button.css`.
The inside Outline border and Ghost's transparent resting surface are preserved.
Default and Icons playground each control variant without extra variant pages.

### Radio Input, Radio Label and Radio Text

All three use native radios, five sizes and an extra-small default. Label hugs
one line with base weight; Text fills its parent and wraps, with the circle at
the top of the first line. Input needs an accessible name or an external label.

```svelte
<script lang="ts">
  import { RadioLabel } from "@stylos/ui";
  let daily = $state<"false" | "true">("true");
  let weekly = $state<"false" | "true">("false");
</script>

<fieldset>
  <legend>Delivery frequency</legend>
  <RadioLabel size="medium" name="frequency" value="daily"
    labelText="Daily" bind:isChecked={daily} isRequired />
  <RadioLabel size="medium" name="frequency" value="weekly"
    labelText="Weekly" bind:isChecked={weekly} isRequired />
</fieldset>
```

Use the same nonempty `name` for options with the same form owner. Give each a
distinct `value`. The browser handles arrows, Tab, validity and form data;
`bind:isChecked` follows deselection too, including selection of a plain native
radio in the same group. Reset restores the initial group defaults and respects
cancellation. `form`, `id`, `accessibleName` and `descriptionIds` work as on Checkbox.
Focus can appear on an unchecked option in an empty group without selecting it.

Radio Text's optional `children` replaces `labelText` with phrasing content such
as emphasis or anchors. Anchor activation follows the link without selecting
the option. No nested labels or additional form controls. Supplementary copy
and errors stay outside the label, associated through `descriptionIds`.

Hover and pressing across the label use the recorded surface roles and
`duration/micro` with `easing/linear`. Reduced motion disables transitions;
forced colors displays the native input. Storybook provides one Default with
Controls per component; static documentation uses the same exported CSS.

### Toggle Input, Toggle Label and Toggle Text

All three render a native checkbox with the switch role, five sizes and an
extra-small default. `isChecked` accepts only `"false"` or `"true"`; the Figma
`mixed` variant has no web API equivalent. Apply the setting as it changes.

```svelte
<script lang="ts">
  import { ToggleLabel } from "@stylos/ui";
  let notifications = $state<"false" | "true">("false");
</script>

<ToggleLabel size="medium" labelText="Notifications"
  bind:isChecked={notifications} />
```

Input needs `accessibleName` or an external label. Label hugs one line; Text
fills the consumer width and centres the track on the first line of wrapping
copy. Its optional `children` replaces `labelText` with phrasing content;
anchors retain their own activation. Keep nested labels and additional form
controls outside the copy. The setting’s label stays the same when switched.

Space and label clicks update the binding. Native `name`, `value`, `form`,
`isRequired`, `descriptionIds` and disabled fieldsets work as on Checkbox;
reset restores the initial selection and respects cancellation. Only checked,
enabled named controls submit. Native validity has no inline error appearance.

Surface colors and thumb travel use `duration/micro` and `easing/linear`
(FND-MOTION-06). Reduced motion removes transitions; forced colors displays
the native input. Storybook has one Default with Controls per component;
static documentation uses the same exported CSS.


### Button Inner

`ButtonInner` is a native `type="button"` local action with no size run or tone.
Supply an icon snippet, an `accessibleName` describing the action and `onclick`.

```svelte
{#snippet clearIcon()}<Icon name="close" />{/snippet}
<ButtonInner icon={clearIcon} accessibleName="Clear field" onclick={clearField} />
```

The icon owns the 40-unit layout footprint; the circular target and hover surface
extend to 140% of it (56 units by default). A parent can set
`--stylos-button-inner-footprint` to a size token and `--stylos-button-inner-color`
to a text-role token. The halo and focus frame follow the footprint's proportions;
leave enough room around adjacent controls. Independent HTML uses the same native
button, an optional `.stylos-button-inner-icon` child and the exported CSS.

`state="disabled"` and native disabled fieldsets suppress activation and focus.
Hover, pressing and keyboard focus are browser states. Motion uses micro/linear
and becomes immediate under reduced motion. Connect supporting content with
`descriptionIds`; an optional surrounding Tooltip repeats the action name.


### Tag

`Tag` renders a non-interactive `span` with `variant="fill" | "outline"` (fill by
default). Both treatments share five
sizes (medium by default), five tones and `textCase="uppercase" | "original"`.
Pass `labelText` in its original case; CSS transforms only its appearance.

```svelte
{#snippet mark()}<Icon name="check" />{/snippet}
<Tag labelText="Complete" tone="success" hasLeadingIcon leadingIcon={mark} />
<Tag variant="outline" labelText="Category" textCase="original" />
```

Optional leading/trailing snippets are decorative; the label carries the meaning.
Their booleans control visibility, and an unassigned snippet renders no slot.
Each icon slot is two units narrower than its icon, preserving Figma’s outward
optical alignment. Outline is painted inside the same footprint, so switching
treatments does not change layout. Size, spacing, radius, type and colors use
tokens. Both text cases use `text-box-trim: trim-both` and
`text-box-edge: cap alphabetic` to centre Figma’s cap-height box without manual
offsets. An `@supports` guard retains normal line-box centring in older browsers.

Tag exposes no state, dismissal or activation. Use it to classify
content. It has Default followed by
Icons playground in Storybook and the same independent CSS for static HTML.


### Tag Interactive

`TagInteractive` uses `variant="fill" | "outline"` (fill by default), with the
same sizes, tones, text cases and decorative icon snippets as Tag. It renders a native button;
`onclick` receives pointer and keyboard activation. `type="button"` is the default;
`submit` and `reset`, with `name`, `value` and `form`, retain native form behaviour.

```svelte
<TagInteractive labelText="Apply" tone="primary" onclick={applyFilters} />
<TagInteractive variant="outline" labelText="Edit" textCase="original" onclick={editItem} />
```

`state="disabled"` and a disabled ancestor fieldset prevent activation and focus.
The browser derives hover, press and keyboard focus. Colours, the outside focus
ring and micro/linear surface transitions use tokens; reduced motion makes the
transitions immediate. Icons remain decorative, with no separate remove action.
No persistent selection or navigation is exposed. Extra small and small preserve
Figma’s 16/20-unit heights; consumers must account for target spacing in their
layouts. It has Default followed by Icons playground and the independent
`@stylos/ui/css/tag-interactive.css` export. Static Tag uses `@stylos/ui/css/tag.css`.


### Migration from separate visual-treatment exports

Replace the component import and supply the corresponding `variant`; other props
keep their names, values and defaults. Figma sets remain separate and are mapped
in each registry entry's `figma.sources`.

Button icon slots now take snippets, matching Link and Tag. Wrap an icon component
in a snippet and pass it as `leadingIcon` or `trailingIcon` with its presence boolean.

| Previous export | Replacement |
| --- | --- |
| `ButtonBase` | `Button` (default base) |
| `ButtonOutline` | `Button variant="outline"` |
| `ButtonGhost` | `Button variant="ghost"` |
| `TagFill` | `Tag` (default fill) |
| `TagOutline` | `Tag variant="outline"` |
| `TagInteractiveFill` | `TagInteractive` (default fill) |
| `TagInteractiveOutline` | `TagInteractive variant="outline"` |

Independent CSS imports move from `button-base.css`, `button-outline.css` and
`button-ghost.css` to `button.css`, from `tag-fill.css`/`tag-outline.css` to
`tag.css`, and from the interactive treatment files to `tag-interactive.css`.
Checkbox, Radio and Toggle retain Input/Label/Text: Label hugs one line, while
Text wraps within its parent and uses a distinct text layout.

### Select

`Select` composes the verified closed field with `Dropdown` and plain
`DropdownItemDefault` options. Bind `value` to the option identifier; empty
string means no selection. Every row needs a unique, non-empty value. The
selected label is resolved from the rows. Supply `inputText` for the initial
selected label when rendering on the server.

```svelte
<script>
  import { Select, DropdownItemDefault } from "@stylos/ui";
  let workspace = $state("design");
</script>

<Select labelText="Workspace" name="workspace" bind:value={workspace}
  inputText="Design" hasClearButton isRequired>
  <DropdownItemDefault value="design" labelText="Design" />
  <DropdownItemDefault value="development" labelText="Development" />
</Select>
```

The full-field button is a select-only combobox. Clear is a separate native
button; `clearAccessibleName` localizes its field-specific name. The hidden
native select owns submission, required validation, autofill and reset. Native
`oninput`/`onchange` callbacks receive that select as their event target.
`id` identifies the visible trigger; `name`, `form` and `autocomplete` are
forwarded to the form control. Read-only stays focusable and submitted but
cannot open or clear; disabled fields and disabled fieldsets leave form data.

The five size profiles, adornments, resting layer-1 shadow and fading focus
halo reuse Input Text CSS. The list uses Dropdown's layer-3 motion and native
scrollbar. Vertical trim follows the Select text layers in Figma: enabled only
for XS–L placeholders, absent for XL and chosen values. Long values truncate
horizontally; option rows retain their full text. `maxHeight` limits the list.
Search, nested Select options and multiple selection remain separate components.

Independent CSS: `@stylos/ui/css/select.css`. Static previews show the closed
field. Storybook has Default, Icons playground and a small Form example for
selection, clear, reset, required validation and disabled-fieldset checks.

### Table core

Use native `<table class="stylos-table">`, `<thead>` and `<tbody>` with
`TableRowHead`, `TableRowBody`, `TableCellHeading` and `TableCellText`.
Column widths belong to the owner, usually through `<colgroup>`. Rows provide
their five-step `size` to all built cells. The web default is `medium`, selected
by the owner; the Figma set default remains `extra small`.
The table keeps native layout, column associations and automatic row height.

```svelte
<table class="stylos-table">
  <thead><TableRowHead size="small">
    <TableCellHeading cellText="Workspace" />
    <TableCellHeading cellText="Amount" alignment="end" />
  </TableRowHead></thead>
  <tbody><TableRowBody size="small" hasDivider>
    <TableCellText cellText="Design" />
    <TableCellText cellText="€24" alignment="end" />
  </TableRowBody></tbody>
</table>
```

Cells keep one main line and an optional qualifier, with complete strings in
the DOM and native `title` attributes. Width-constrained text uses horizontal
ellipsis without clipping glyphs vertically. Vertical trim remains off.
`alignment="end"` mirrors the icon and controls; lining/tabular numerals match
Figma. `id` identifies either cell; Text's `headers` supports complex native
associations. Heading always uses `scope="col"`.

An already constrained heading shows its sort/filter Button Inner controls.
`isSorted` and `sortDirection="ascending|descending"` expose `aria-sort`;
`isFiltered` shows the filter control. Both flags share one bottom mark.
Set localized `sortAccessibleName` and `filterAccessibleName` as needed.
`onclick` receives the native click from either control; its button's nearest
`[data-table-action]` wrapper identifies `sort` or `filter`. The owner updates
the state and data. Initiating constraints through a menu remains a later slice.

Body rows accept `hasBackground` and `hasDivider`; the owner chooses banding.
Browser hover changes only enabled backgrounds, preserving the current Figma
limitation on plain rows. It uses micro/linear Motion, immediate in reduced
motion. Rows carry no activation, selection or keyboard-grid behaviour.

Each component has an independent `@stylos/ui/css/table-*.css` export. Import
the CSS of children as well when composing native HTML without Svelte.
Storybook has Default for all four, Icons playground after the cell Defaults,
and Table under Table Row Body with real sorting and filter clearing.

### Modal and Drawer

Both share five size profiles and a `medium` default. `Modal` uses native
`showModal()` and level-6 free entry; `Drawer` uses non-modal `show()`, level 5
and physical `position="left|right"` edge travel. Window widths are the contract's
400/500/600/700/800 px exceptions above the dimension scale; `width` accepts an
optional CSS length override, capped by the viewport.

```svelte
<script>
  import { Modal, Button } from "@stylos/ui";
  let open = $state(false);
</script>
<Button labelText="Edit workspace" onclick={() => { open = true; }} />
<Modal bind:isOpen={open} headingText="Edit workspace"
  primaryButtonText="Save" onprimaryclick={() => { open = false; }}>
  <!-- Supply a short task with existing content styles/components. -->
</Modal>
```

`headingText` names the native dialog; `id` derives its heading association.
`hasPrimaryButton`, `hasSecondaryButton` and `hasTertiaryButton` retain Figma's
fixed action order. When all three flags are false, the whole footer is absent.
Their `*ButtonText` labels and `closeAccessibleName` are
localizable. Named `onprimaryclick`, `onsecondaryclick` and `ontertiaryclick`
handlers receive the native Button click. Cancel closes unless its handler
prevents default. Primary and tertiary handlers decide when the task completes.
The close control remains present. `onclose` receives the native close event
once dismissal finishes.

Escape closes the top active window after any anchored child handles it.
Focus moves inside; an `autofocus` control in content can choose the target,
otherwise Close receives it. Modal contains focus and locks page scrolling
until exit finishes; locks survive nested modals and restore the prior styles.
Drawer keeps the page and its tab order operable, returning focus when dismissed
from within the drawer and preserving focus already moved to a page task.
Neither window dismisses through an outside click. Set `isOpen=false` for the
animated close path; direct native `dialog.close()` remains an immediate close.

Drawer fills the viewport, fixing its header/footer around a named, focusable
scrolling content region. Its medium/absolute scrollbar follows Figma and the
accepted native-browser CSS differences. Modal's content hugs its task; the
host can scroll the whole panel on a small viewport as a fallback. Heading
Vertical trim stays off. Figma supplies no backdrop colour, so the modal's
native backdrop is transparent; a product can supply `--stylos-window-backdrop`.

Dropdown, Select and Tooltip adapters keep their portals inside the owning
window's full-viewport host, outside its clipped panel, and dismiss with it.
This preserves native modal interaction and prevents child popup clipping.
Motion reuses the shared level and attachment profiles, handles interrupted
closing/reopening and completes immediately with reduced motion.

Independent CSS: `@stylos/ui/css/modal.css` and `drawer.css`; native HTML owners
can use `@stylos/ui/behaviors/window` with the same dialog/panel markup and
`WindowBehaviorOptions`. Static previews show only the frame (the Drawer
preview supplies its own illustrative viewport height). Storybook retains
Default and one Form example per window, including Select and nested confirmation.
