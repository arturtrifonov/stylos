# Stage 5 — 0.2.0 acceptance

**Scope changed 2026-10-17:** the owner added nine urgent product components and
three compositional dependencies to the starting set, retaining draft contracts.
The measurements below are the **2026-10-14 baseline for the earlier 34-core set**;
they do not certify the expanded set. Fresh expanded-set evidence is recorded in
[starting-set-2026-10-17.md](starting-set-2026-10-17.md). Existing manual
observations remain useful, but Chrome/Orca evaluation is still pending.

This is measured evidence and remaining work, not a release or a conformance claim.
The release criteria remain in [PLAN.md](../../../PLAN.md#020). The package is
still private and versioned 0.1.0; the owner performs the release after acceptance.

## Scope

All 34 core entries named by the plan have implementations. Tag Interactive is
an additional implemented entry outside this acceptance scope. The case generator
exhausts each core entry's variant product, including visibility gates for open
Modal/Drawer and sorted Table Cell Heading, and exercises other booleans independently:
1,949 configured cases. Arbitrary text, icon choices, slot contents and combinations
of multiple optional booleans are not exhausted. Figma pixel parity is not tested
by this harness.
Variant assertions use the DOM contract's attributes and native semantics;
Tooltip placement is a behaviour setting without an SSR attribute and its
collision/positioning geometry remains part of representative manual checks.

Browser checks used the Codex in-app Chromium engine on Linux x86_64,
reported as Chrome 154.0.0.0. axe-core is locked at 4.14.0. This is browser
evidence, not an Orca evaluation. Raw reports are generated under
`build/ui-release/`; browser results include the user agent, time, case totals,
failure details and a fingerprint of the tested sources and built artifacts.
Reports use schema version 2 and validate all count/array fields. Missing or old
evidence requests a fresh browser run. Requests preserve split UTF-8 characters;
oversized reports get an explicit 413 response. They are not committed.

Review corrections also uncovered an actual packaging failure: `.svelte` and
`.js` output imported absent `.ts` files. `rewriteRelativeImportExtensions` now
emits `.js` paths while source imports remain `.ts` for the existing native tool
tests. The packaged render pass verifies those imports. Default table fixtures
now share `.stylos-table` and native body rows with the workshop; Dropdown's group
branch forwards its arguments and uses the native-control adapter. Quoted boolean
defaults are normalized in `loadRegistry`, including for component-page examples.

The incomplete axe checks are the same seven cases in each theme: a one-character
Badge whose contrast axe cannot classify as text, an empty Input Text value,
Select value contrast obstructed by the native field overlay, and closed
Dropdown/Select `aria-controls` relationships, plus header contrast in the native
Table Row Head/Body fixtures, whose pseudo-element backgrounds axe cannot resolve.
Those four table/theme findings became visible when the harness reused the actual
workshop table styling. These are unresolved automated
checks, not passing results. Inspect filled fields and selected values, verify
contrast under their actual backgrounds, and check the popup relationships in
closed and open states. The harness preserves all targets and explanations in
the raw report. Other variants receive rendering coverage, not exhaustive axe
audits or visual comparisons.

## Observed keyboard and form behaviour

The browser harness exposes **Inspect component** → **Show Default example**.
These checks used real browser keyboard/pointer input in the same Chromium engine:

| Composition | Observed result |
| --- | --- |
| Native controls form | Space changes Checkbox mixed → checked and toggles the switch; Radio ArrowRight skips disabled Research and selects Pro; native submission includes selected named values |
| Native controls form | Reset restores Checkbox mixed, Toggle false and Standard selected; a disabled fieldset makes every control unavailable and submits no values |
| Select | ArrowDown opens; movement skips disabled Research; Enter selects Operations, closes and returns focus to the field |
| Modal form | Select opens above the Modal; first Escape closes Select and returns focus to it; second Escape closes Modal and returns focus to Edit workspace after exit |
| Drawer form | Find workspace remains operable while Drawer is open; its Save action opens a modal confirmation; Escape closes that child and returns focus to Save while Drawer remains open; the next Escape closes Drawer |

These observations cover representative compositions only. Browser assertions
do not report what a person hears through assistive technology.

## Manual Chrome and Orca evaluation — pending

The owner selected Linux + Chrome + Orca. Installed packages at preparation were
Google Chrome 154.0.8037.92 and Orca 50.2 (distribution package
50.2-0ubuntu0.1). Record the versions actually used and the results here when
performing the evaluation. No speech or braille output was evaluated by the agent.

In Chrome, open the browser harness and use its inspection compositions:

1. **Native controls form:** check spoken names, checkbox mixed/checked states,
   switch state, Radio group and disabled-option announcements; use Space,
   arrows, Submit, Reset and Disable fieldset. Confirm announcements match the
   submitted values and restored bindings.
2. **Select form / Dropdown / Nested navigation / Dropdown controls:** check
   names, current values, expansion, highlighted and selected options, disabled
   rows and level changes. Confirm Tab and Escape leave focus at the expected
   control and do not strand the user in a portaled surface.
3. **Modal form:** check the window title and initial focus, contained tab order,
   field names, nested Select, child-first Escape and return to the opener.
4. **Drawer form:** confirm the surrounding page stays available, the Drawer
   title/content are discoverable, and a nested Modal temporarily contains
   interaction and returns focus to the Drawer action.
5. **Tooltip / Table Cell Heading / Table Cell Text:** check keyboard-triggered
   descriptions and native column-header/cell relationships. Review the
   incomplete axe checks listed above, including filled/selected content and
   numerical Badge contrast, in light and dark themes.

For every observation, record composition, state, theme, exact browser/Orca
versions, expected announcement, actual announcement and any unresolved finding.
This manual evaluation and review of incomplete checks remain before recommending
the Stage 5 release. Full-product conformance is assessed separately in Stage 6.

## Repeat the checks

```bash
npm ci
npm test
npm run validate:registry
npm run validate:rules
npm run validate:skills
npm run tokens:check
npm run lint:css
npm run ui:check
npm run ui:build
npm run workshop:build
npm run build
npm run ui:verify
npm run ui:verify:browser
```

Open `http://127.0.0.1:4174`, use **Run browser checks**, and then run
`npm run ui:verify:results` in another terminal. It rejects stale evidence,
incomplete rendering and detected violations, and reports incomplete axe checks
for manual review. A site rebuild clears `build/`, so rebuild acceptance artifacts
and record fresh browser results afterwards. CI performs the build/server checks;
the browser run and assistive-technology evaluation are separate steps.
