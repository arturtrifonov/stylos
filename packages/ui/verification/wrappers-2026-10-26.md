# Jobless wrappers — component review, 2026-10-26

## Scope and decisions

The owner asked for a review of every implemented component in `packages/ui`
for wrappers that do no work, then for this pass to remove them ("PR A"). The
rule is the package guide's: an element exists only for a semantic,
accessibility, layout, positioning or behaviour need that an existing element
cannot meet. The review's other findings (behaviour adapters, Alert live
regions, the Accordion landmark) are out of scope here.

**Owner decision, 2026-10-26:** Table Cell Heading reports `onsortclick` and
`onfilterclick`. They replace the single `onclick`, which the consumer could
only tell apart by the `data-table-action` wrapper around each control. The
contract records the change.

**Owner decision, 2026-10-26:** Dropdown keeps `ul` and `li role="presentation"`
around action and control rows. The list is the panel's semantics, not a
wrapper.

## Removed

One technique replaces every icon slot. The slot was narrower than its icon by
Figma's optical overhang, and the icon overflowed it toward the outer edge.
Now the icon renders directly, keeps its footprint, and the padding on its side
gives way: `data-leading-icon` and `data-trailing-icon` on Button and Tag,
`data-leading-icon` and selection on Dropdown rows, `data-icon` on table frames.
Where the icon is not at an edge (Accordion Header's supplied icon, Select's
chevron and clear), a negative logical margin does the same.

| Component | Removed |
| --- | --- |
| Button | label span; leading and trailing icon slots |
| Button Icon, Button Inner | icon slot |
| Tag, Tag Interactive | leading and trailing icon slots (`.stylos-tag-label` stays for `text-box-trim`) |
| Checkbox, Radio and Toggle Input | surface element: the root span is the surface, the mark its pseudo-element |
| Checkbox, Radio and Toggle Label | copy span: the label text is a text node |
| Dropdown Item Default, Parent | leading, selection check and arrow slots |
| Dropdown Item Checkbox, Toggle | control slot |
| Select | adornment overlay, always-rendered side groups, the inner value span, the clear wrapper and both icon slots; Select now uses Input Text's compact field structure |
| Modal, Drawer | close wrapper and footer action group |
| Alert Inline, Alert Popup | icon slot (the icon centres on the first heading line by its block margin) |
| Alert Popup Timer | inner header row; Close takes the outer spacing as its start margin |
| Accordion Header | supplied-icon slot |
| Table Cell Text, Table Cell Heading | icon slot; Heading's two action wrappers |

## Kept, with their jobs

- **Tooltip root** (`display: contents`) and Tabs Horizontal's overflow holder:
  each is the Svelte block boundary for a positioner that is moved into the
  overlay host. Svelte removes a destroyed block by walking siblings from its
  first to its last node before the action's `destroy` returns the positioner,
  so a portalled last node would make that walk remove unrelated siblings.
- Field leading and trailing groups (absolute positioning and measured text
  reserve). Input Text's trailing icon slot inside its trailing group does the
  same overhang job as the removed slots; it is left for a follow-up because
  Input Text's reserve rules and preview tests are keyed to it.
- `.stylos-tag-label` (`text-box-trim`), Accordion title, Dropdown and table
  labels (horizontal ellipsis), Checkbox/Radio/Toggle Text copy (wrapping
  phrasing content), Link content (decoration box), the table cell frame,
  the Alert body, content and actions, and the Timer progress holder (it hides
  a redundant visual from assistive technology).

## Rendering

Static Storybook builds of `master` (4c76211) and this branch were compared
pixel by pixel in headless Chrome 154 at 1280 × 900, with transitions and
animations stopped and focus emulated in every tab:

- every story at its defaults (93 stories);
- argument permutations through the Storybook channel: five sizes; leading,
  trailing and both icons for Button and both Tags; selected and unselected
  rows with and without icons; Checkbox and Toggle rows at both alignments;
  Select with validation, disabled and empty states; table cells at both
  alignments, sorted and filtered; checked, mixed and disabled controls;
  Timer with Close and content; open Modal and Drawer with three actions;
  Alerts; Accordion Header with a supplied icon at both positions;
- keyboard focus by trusted Tab presses and forced colours for the controls,
  rows, Select, Buttons, Tag Interactive, the table heading, Modal and Alerts.

Results: all 93 default stories are identical. Of 275 permutations, 265 are
identical and the 10 that differ are all Dropdown Item Toggle with start
alignment, at every size and in both selection states (the fix below). Of 54
focus and forced-colour cases, 50 are identical and the four that differ are
the same Toggle row. One forced-colours difference, an Alert icon that kept
its author colour once it was no longer inside an HTML slot, was fixed: in
forced colours the icon inherits the alert's system colour, and all 19 Alert
cases are now identical. Measured element positions match too, for example
the Alert Popup icon at 13, 15 and 20 × 20 on both builds.

The review plays — Accordion, Alerts, Progress Bar, Switcher, Tabs,
Typography, the forms, Dropdown, Table and Link — all finish without an
exception (31 stories, read from Storybook's channel events). Two plays were
corrected on the way: Alert Inline **Variants** measured a Close button its
samples do not have (it failed on `master` too), and Tabs **Overflow**
compared the menu with the hidden set read before late font loading could
return a tab to the row.

## Fixes found on the way

- **Dropdown Item Toggle** placed its switch 2 px further in than Dropdown Item
  Checkbox placed its box. The control slot positioned its child absolutely,
  but Toggle Input's own `position: relative` won by stylesheet order, so the
  intended outward overhang never applied and the switch crowded its label.
  Both rows now give the overhang back the same way: the control starts
  `padding − overhang` from the row edge (6 px at Medium, measured on both
  rows) and the label does not move. End alignment was already right.
- **Right-to-left overhang.** Button, Tag, Select and Input Text's trailing
  icon slot anchored their icons with physical `left` and `right`, so in RTL
  the icon sat at the full padding and its overhang pointed inward. Measured
  with `dir="rtl"` at Medium, the outer gap is now padding − optical on both
  sides: Button 18 (was 20), Tag 8 (was 10), Input Text trailing icon 10 (was
  12), Select chevron and leading icon 10 (were 12). Dropdown rows and
  leading field icons already used logical insets and are unchanged.
- Overrides that a shared stylesheet could undo when it is imported again by
  another component use compound selectors (for example
  `.stylos-dropdown-item.stylos-dropdown-item-parent`), as `selection.css` does.
