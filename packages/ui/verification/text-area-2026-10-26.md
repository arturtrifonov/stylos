Body, message and counter use Georama Regular 400; Label uses Georama 450.
The native textarea's three line boxes replace Figma's trimmed text drawing.
Its initial height is two body line heights plus the matching single-line
field height, with a one-line minimum and native vertical resizing. Only the
native value is rendered; no duplicate text layer is used.

Text validation reserves the full square glyph width, without optical width
compensation. Its larger circular backdrop overhangs the square. The Text Area
glyph occupies the same top/right position, with its backdrop centred around
it, but is an absolute overlay and does not change textarea text padding.
A configured trailing snippet retains its own reserve and moves the status
before it to prevent their collision. Optional decorative marks retain their
own optical boxes. Component-specific rules outrank shared field rules so
import order cannot restore the old compensated validation width.

Search's 50 current Figma variants have no validation dimension. The public
validation prop, wrapper outcome, status, aria-invalid and related preview
branches were removed; optional supporting hints remain associated. Its
permanent search mark and native clear action are preserved. Prior Search
validation observations in its earlier evidence describe the superseded API.

## DOM and API

The plain labelled Text Area renders four elements: root, label, field and
textarea. The field owns positioning, surface effects and a local stacking
context. There is no common adornments overlay, no empty side group, no text
wrapper and no extra container around the counter. Each optional icon owns one
slot, including its existing SVG/path. Validation is a direct child of the
field and does not need a trailing row. Surviving elements retain their shared
hierarchy when properties change.

Medium is the default; placeholder and counter are off. Counter copy derives
from the native UTF-16 length, normalizing CR/CRLF to LF. A valid numeric
maxlength adds the denominator; no implicit limit is introduced. Custom
counterText is optional display copy. Numeric maxlength/minlength accept zero
and other nonnegative integers; invalid limits are omitted. Existing values
are never silently truncated. Migration is recorded in the contract and guide.

## Browser and functional evidence

- All five Text Area densities measured the geometry/type profiles above.
  Validation-only padding remains the plain-field padding (7/9/11/15/19 CSS
  units inside the one-unit border). Adding a trailing icon measures its own
  reserve; it does not collide with the separate status.
- Native drag resized Medium from 108 to 208; the status glyph stayed at top
  12 and the backdrop at top 8. Multiline input has native overflow. Typed text
  survives density changes and switching editable/read-only/disabled modes.
- Tab reaches the textarea and matches focus-visible. Read-only is native and
  retains its value; disabled is unavailable. Both suppress the authored status.
- The packaged Native controls form submitted a multiline notes value with its
  newline, then reset both binding and counter to Initial notes / 13 of 40.
  Typing beyond maxlength 40 retained 40 units and displayed 40 / 40. Disabling
  the enclosing fieldset disabled the textarea.
- Current Text validation slots and their SVGs measure equal width and height
  at every density. Search Controls have no validation group; its input has
  no aria-invalid attribute or status mark.
- Unit/preview checks cover defaults, native escaping, no empty groups, direct
  validation placement, counter descriptions, UTF-16/newline accounting,
  custom/empty counter copy, zero limits and rejected invalid constraints.

Text Area is ready after this scoped owner-directed review. Four urgent
starting-set contracts remain draft: Switcher, Switcher Item, Tabs Horizontal

Release-wide Chrome/Orca evaluation, contrast and complete two-theme
accessibility acceptance remain in [0.3.0](0.3.0.md). This review does not claim
those checks passed. Pre-existing Figma typography outliers outside Text Area
(one Small Input Text value and older suffix font bindings) were observed;
this implementation does not edit those design nodes or redefine the shared
normal font token from them.
