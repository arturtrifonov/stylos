# Tabs — component alignment, 2026-10-26

## Scope and sources

Owner-directed alignment of Tabs Horizontal and Tab Item with the Figma sets
the owner finished on 2026-10-26, with the same DOM rule as Switcher: no
element without a job. Read-only inspection covered page 1506:143081 of
Components file WUc07ZBtjRvypXtsOlbVut: Tabs Horizontal 4451:19901 (5 sizes ×
`is focused`), Tab Horizontal Text 4451:16154 (40 variants) and Tab Horizontal
Icon 4848:4130 (40 variants). Design contexts were taken for every size of the
group and of selected text and icon tabs, and for Medium hover, active and
disabled in both selection states. Figma's item-level `is focused` is the
owner's exploration and was not implemented. The older documentation frame on
the page (three sizes, navigation arrows, search-and-apply overflow) predates
the sets and was not used. No Figma node was edited.

**Owner decisions, 2026-10-26:**

- The icon-only set becomes a separate draft entry and component, Tab Item
  Icon, as with Switcher Item Icon. It joins wave 7 (PLAN §4.1).
- Overflow is automatic. Tabs that do not fit move into a Dropdown of Dropdown
  Item Default rows; choosing a row selects that tab and closes the menu. The
  selected tab always stays in the row, taking the last place that fits.
- Medium is the default size of all three.
- The indicator travels like Switcher's.
- Focus is drawn on the row (Figma Tabs Horizontal `is focused`). Activation
  stays automatic: APG recommends it when panels display without latency, and
  the consumer's panels are mounted.

## Focus and keyboard

Native semantics are unchanged: one tab stop for the tablist, arrows and
Home/End move focus and activate (skipping disabled and menu-held tabs), Tab
leaves for the panel. While a tab matches `:focus-visible`, the row shows a
frame in the field focus treatment — `border/primary`, `background/base`,
`focus/base`, radius large — crossfaded with `micro`/`linear`. Tabs draw no ring.
The overflow trigger is a separate tab stop with its own `focus/base` frame
and inset primary border. Forced colours use Highlight outlines and indicator.

Trusted input in Chromium: a pointer click drew no frame; Arrow Right moved
focus and selection to the next tab, showed the frame (3 above, 15 = 12 + 3
beside at Medium) and slid the indicator from 12 to 126.5; Tab removed it.
Tab from the selected tab reached the trigger, framed alone.

## Overflow

`tabsBehavior` measures tab widths (ResizeObserver) and, when they do not fit,
marks the tabs that leave the row `data-overflowed`; Tabs Horizontal then
renders the trigger and menu. `fitTabs` keeps document order, gives way for
the selected tab and tolerates half-unit rounding. The trigger is Tab Item Icon
with `more_horiz`, named "More tabs" (`moreAccessibleName`); it uses the
shared Dropdown adapter, now with `sameWidth: false`, so the menu sizes to its
rows and aligns to the trigger's end. A tab chosen from the menu receives
focus once the menu closes.

Headless Chrome 154, real frames and input, a 30rem row of eight tabs: four
visible and four in the menu; widening to 70rem removed the trigger, menu and
positioner; narrowing to 26rem restored them; choosing Archive (pointer)
selected it, moved it into the row, displaced Members, focused it and fired
one change. In the Claude browser pane the keyboard path — Enter on the
trigger, Arrow Down, Enter — selected Integrations, focused it and showed the
row frame. Firefox 156 produced the same overflow layout and indicator
alignment; its indicator moves without travel (bug 1924226, as Switcher).

Two defects found during this review were fixed: a tab chosen from the menu
was briefly unselected because the initial-selection check ignored menu-held
tabs, and the menu passed the selected tab's value, which left keyboard
highlight on a row that does not exist.

## DOM

Counts include every element, SVG and path included:

| Configuration | Before | After |
| --- | ---: | ---: |
| Plain tab | 2 | 1 |
| Tab with leading icon | 5 | 3 |
| Tab with Badge | 3 | 2 |
| Three plain tabs with their row | 8 | 5 |

Removed: the label span (the button is the label box), icon slot spans (the
Icon renders directly; the overhang is a padding reduction), `data-is-selected`
(`aria-selected` drives styling) and the per-tab indicator (one anchored
pseudo-element per list, with a per-tab fallback without anchor positioning).

Retained: the row (bottom line, focus frame, and the trigger beside the
tablist, which may only contain tabs) and the tablist. Panels now render after
the row instead of inside the component root. The overflow trigger, its
`display: contents` holder and the menu exist only while tabs overflow.
