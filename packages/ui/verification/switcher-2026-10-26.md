## Focus

Native radios keep their semantics: one tab stop per group, arrows move focus
and the checked state together, and assistive technology announces the
focused radio. Only the drawing moved. While any segment's radio matches
`:focus-visible`, the fieldset takes `border/primary` and the field focus
effect `focus/base` in place of its resting elevation, in both tones, as the
Effects foundation describes for Input Text. The effect sits on the
fieldset's `::before` and crossfades with `micro`/`linear` like the fields'
effect layers; reduced motion makes it immediate. Forced colours remove
shadows, so a Highlight outline marks the focused group. The segment-level
focus outline from the shared selection sheet now applies only to Tab Item.

The focused radio is the checked one, so the selected surface shows where
focus is. When the checked radio is disabled, Tab reaches an unchecked one;
that segment then shows the hover surface. Figma has no drawing for this case.

Trusted keyboard and pointer input in Chromium (synthetic `userEvent` input
does not set `:focus-visible`, so the stories do not assert it):

| --- | --- | --- | --- | --- |
| Pointer click on List | list | off | `border/default` | elevation 1 |

| Tab to Reset | — | off | `border/default` | elevation 1 |
| Shift+Tab back | grid, checked | `focus/base` | `border/primary` | none |

## Sliding selection

Selection stays item state: the native radio's `:checked`. Only its bold
surface moves to the group, because one surface can travel and per-segment
fills can only swap. The fieldset's `::after` is anchored with CSS anchor
positioning to the checked segment (`anchor-name` set through `:has()`,
`anchor-scope` on the group), so it adds no element and needs no script.
Inside such a group a shared custom property makes segments' own selected
fill transparent; their hover, press and disabled tints are unchanged, and
the indicator takes the selected hover, press and disabled surfaces through
`:has()`. Where anchor positioning is unsupported, the segment paints its
fill in place as before. Forced colours hide the indicator and return
Highlight to the segment.

The travel is a CSS transition of `left` and `width` whose values come from
`anchor()`. CSS Anchor Positioning resolves `anchor()` at computed-value time,
so a change of the element carrying the anchor name is a computed-value
change that starts transitions
([csswg-drafts #8181](https://github.com/w3c/csswg-drafts/issues/8181)).
Engine support differs:

| Engine | Anchor positioning | Travel |
| --- | --- | --- |
| Chromium 152 (Claude browser pane), Chrome 154 headless | yes | yes |
| Firefox 156 headless | yes, with `anchor-scope` | no: no transition is created; the surface moves instantly and colours fade |

Firefox shipped anchor positioning as an MVP without style/layout
interleaving, tracked as [bug 1924226](https://bugzilla.mozilla.org/show_bug.cgi?id=1924226)
(NEW, unassigned on 2026-10-26). Disabling this review's focus additions in
Firefox did not change the result, so the gap predates them. Safari was not
tested.

**Owner decision, 2026-10-26:** no script-measured fallback. The component
uses the specified mechanism, and Firefox gains the travel when it implements
it; until then it degrades to an instant move.

Motion record (FND-MOTION-15), as recorded in the Switcher contract:

| | Value | Rule |
| --- | --- | --- |
| Trigger | the checked radio changes (pointer, arrows, binding, reset) | FND-MOTION-01 |
| Animated | indicator `left` and `width`; segment text `color` | FND-MOTION-11 |
| Profile | `medium/enter` (220 ms) with `enter`, no overshoot | FND-MOTION-04, -05, -02 |
| Departure | from local-state `micro`/`linear`: the change travels | FND-MOTION-06 |
| Interruption | continues from the presented position | FND-MOTION-10 |
| Reduced motion | immediate | FND-MOTION-13 |

Chromium 152 measured the transition from Option 1 to Option 4 at Medium: the
indicator's left edge was at 1 / 186.9 / 234.6 / 243.2 / 243.9 px at 0, 55,
110, 165 and 220 ms, while Option 4's text moved to inverted on the same
curve and Option 1's back to base. A second change during a transition
started from the presented value. On the CSS-only page, with no script, the
indicator matched the checked segment exactly (3.00, 217.58 and 324.87 px
left; widths equal) and transitioned between them in Chromium. Headless
Chrome 154 screenshots taken during real pointer and keyboard input, without
script in between, showed the surface between segments mid-transition.
Reduced-motion and forced-colours rules were reviewed in code; they were not
emulated here.

Removed:

- The label text span: the label is the flex row and carries the text node.
- Each icon slot span: the Icon renders directly, its footprint comes from
  the segment, and the overhang is a padding reduction. Accordion Header already
  places its Icon without a slot. Icon is aria-hidden itself.
- `data-is-selected`: selection follows the native radio through `:checked`.
  The CSS-only page now shows selection changes without any script.

Retained:

- The fieldset: native grouping, its accessible name and disabling every radio.
  Figma's content-slot frame has no counterpart; the fieldset lays out segments.
- The label: the segment surface and its native association.
- The radio: semantics, keyboard, form data and reset. It covers the segment
  transparently as the hit target.

The icon snippet should render one Icon; the segment does not wrap or hide
other content. That expectation is in both item contracts. The sliding
indicator is a pseudo-element and adds no element to these counts.

## Browser and functional evidence

- The Switcher **Review** story checks all five sizes in both tones for text,
  icon, icon-only and disabled groups: inset, border colour, group and segment
  heights, gaps, padding, icon sizes, optical offsets, selected/rest/disabled
  colours, the indicator's surface and its exact alignment with the checked
  segment, and element counts. It passes in light and dark schemes.
- Pointer hover measured `surface/subtle/primary/hover` on an unselected
  Primary segment and `surface/bold/primary/hover` on the selected one.
- The **Keyboard and form** story: the group is named, Arrow Right moves the
  checked radio and focus to the icon-only segment and starts a 220 ms `left`
  transition on the group's `::after` towards it, form data carries its value,
  Reset restores the initial value and binding, and a disabled segment stays
  disabled. Reset is mirrored after an animation frame; the browser pane was
  hidden and produced no frames, so this run substituted a 16 ms timer for
  `requestAnimationFrame`. Without that substitution the story fails at Reset
  in a hidden pane only.
- On the packaged CSS-only page, clicking a radio moves the selected surface;
  the icon-only sample measures 20 by 20 with a 14-unit icon and keeps its
  aria-label.
- Tabs Horizontal's Tab Item keeps its 24-unit label box, 8-unit padding and
  4-unit band after the shared stylesheet change.
