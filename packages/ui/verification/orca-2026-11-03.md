## Causes

Five causes explain the eight confirmed failures:

1. **Flex labels split a control from its text** (N5, D3): Checkbox, Radio and
   Toggle Label, and Dropdown Item Checkbox and Toggle rows.
2. **`aria-label` duplicates a visible label** (W1, D3): Input Text, Select,
   and the checkbox and toggle inputs of Dropdown rows; the label is then not
   related to its control, so Orca reads it as stray dialog text.
3. **Alerts appear with their live region already filled** (P8), and Timer's
   container is not itself the status (P9); focus after Undo is the host's.
4. **The sort and filter buttons join the column header's name** (C2).
5. **Select suppresses its clear button's ring** (S6); the counter speaks bare
   numbers (N7) — a content decision.

The Orca debug log of the re-run is the evidence for 1 and for P3's open state.

## Fixes

Made on `claude/stylos-status-ec198e` by owner decision ("as recommended"),
for re-check in the walkthrough's second round:

1. Checkbox, Radio and Toggle Label and Text, and Dropdown Item Checkbox and
   Toggle lay the control and its text out inline. In a probe Chrome read over
   AT-SPI — Orca's own source of lines — each label is now one line
   (`[obj]Standard`, `[obj]Receive updates`), where it was two (`[obj]`,
   `Standard`). Every decorative pseudo-element carries `content: "" / ""`.
2. Input Text, Text Area, Input Search and Select name themselves from the
   label text by `aria-labelledby` (Label's new `label text id`); Dropdown
   rows name their input from the label text (`label ids` on Checkbox, Radio
   and Toggle Input). No field repeats its visible label in `aria-label`.
3. Alert Inline, Popup and Popup Timer stay in the DOM while closed, as empty,
   visually hidden live regions. Timer's section is its live region; its
   counter is `aria-live="off"`. The starting-set example returns focus to
   Show notifications after Close and Undo, as a host does.
4. A header with sort or filter buttons is named by its text alone.
5. Select's clear button keeps Button Inner's ring; the field shows no focus
   meanwhile.
6. Text Area describes its counter in words ("13 of 40 characters";
   `counter accessible text`).
7. Drawer's content region is a tab stop only while it holds nothing focusable.

Rendering was compared pixel by pixel against `31814e9` in headless Chrome 156
at 1280 × 900 with transitions off: 437 renders of the affected components
across their sizes, states, selection, supporting text and alignment; 381 are
identical. The other 56, all Dropdown Item Checkbox and Toggle rows with the
control at the start, differ in 1–3 pixels of anti-aliasing at the first
glyph (at most 19 of 255 per channel); their geometry matches to 0.01 px.

## Third round — alerts opening

P8 traced in Orca 50.3's own source (`event_manager.py`, `live_region_presenter.py`).
Its event manager drops an event when one of the same type from the same
application arrived less than 0.1 s earlier. It exempts a text insertion only
when the source is a plain `section` with a live politeness, and an alert's
`role=status` section is a status bar, not a section. Opening one alert inserts
its heading, content and buttons as separate insertions within a millisecond, so
only the first is handled: in the owner's log a button, which the live-region
presenter takes as its own atomic container and does not speak.

Fix: each alert announces through a visually hidden announcer, a plain
`aria-live` span inside its section, which receives one text node on opening.
For Inline and Popup that is the heading, then the content ("Workspace imported.
Your workspace is ready."); for Timer the heading only, as its contract's
`heading text` already states, so neither the counter nor Undo is heard. The
section keeps its role and its heading as its name, so focus entering it still
says "Workspace imported, status bar"; it is `aria-live="off"`, so its own
insertions are not a live region. The announcer is emptied after 7 seconds, so
reading the page does not meet the text twice, and the state at mount is not
announced.

In a probe Chrome 156 read over AT-SPI, Show notifications on the starting set
now produces three live insertions, one per alert, each from a live `section`
(`stylos-alert-announcer`): the full message of each alert. The other 11
insertions of the burst are in regions with `container-live:off`. Closing one
alert and showing again produces one insertion; nothing is inserted at page
load. Real key presses through the updated P9 and P8 steps reach Undo, the
Popup's and Inline's Close and Show notifications as written; the example now
returns focus after Popup's Close too.
