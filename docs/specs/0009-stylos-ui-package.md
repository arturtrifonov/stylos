# SPEC 0009 — `@stylos/ui`

**Status:** Open — written 2026-09-06
**Date:** 2026-09-06

A work order for the code package, the second half of [`PLAN.md`](../../PLAN.md) Stage 5. The stack is decided in [ADR 0002](../decisions/0002-frontend-stack.md); this says what to build. The CSS build it consumes exists ([SPEC 0007](0007-tokens-to-css.md)); the flow it is built inside exists ([SPEC 0008](0008-development-and-release-flow.md)).

The `0.2.0` gate ([`PLAN.md`](../../PLAN.md) §1): tokens are consumable as CSS (done), `@stylos/ui` builds the core set, and every component's props map onto its contract's `api`.

## 1. Layout

npm workspace. `packages/ui` is `@stylos/ui`; `apps/workshop` is Storybook. `tools/` stays where it is and gains generators (§4) that read the registry and write into `packages/ui/src`.

```
packages/ui/
  src/
    tokens.css              generated by tokens:css (SPEC 0007)
    components/<name>/       one directory per component
      <Name>.svelte
      <name>.css
      props.ts              generated from the entry's api
    behaviors/              framework-free: dialog, listbox, menu, tooltip, …
    index.ts
apps/workshop/              Storybook 10, Svelte CSF
```

`packages/ui/dist/` already holds `tokens.css`; it stays gitignored ([SPEC 0007](0007-tokens-to-css.md)). `tokens:css` runs as the package's `prebuild`.

## 2. The layers, top is thinnest

Fixed by [ADR 0002](../decisions/0002-frontend-stack.md); repeated here as the build order.

1. **`tokens.css`** — the custom properties. Nothing below restates a value.
2. **Per-component CSS**, selectors keyed on data attributes that carry the contract's values: `.stylos-button[data-tone="primary"][data-size="medium"]`. Every value is a `var(--stylos-…)`; a hex or a raw `px` outside `tokens.css` fails Stylelint (§6).
3. **Behaviour** — a Zag machine or a platform feature, attached to the DOM with `{@attach}`. Framework-free where it is ours (`src/behaviors/*.ts` operate on elements, not on Svelte).
4. **`.svelte` wrapper** — takes the contract's props, spreads the machine's prop getters onto its own elements, writes the data attributes CSS reads. The wrapper is the only Svelte-specific file; layers 1–3 survive a framework change.

## 3. The property mapping rule

The `0.2.0` gate says props map 1:1 onto Figma variant properties. Read literally against the registry that is wrong — 68 boolean `has X`, `state`, and `is focused` are not props — and the fix Artur set is that `api` describes the web component, not the Figma file ([registry work below](#5-registry-work-first)). So the gate is **props ↔ the entry's `api`, 1:1**, and the rule from `api` to a prop is:

| `api` kind | Prop |
| --- | --- |
| `variant` | one prop, camelCased name (`text case` → `textCase`), value is the value string verbatim |
| `text` | a string prop |
| `boolean` | a boolean prop |
| `instance` | a prop taking a component or snippet |
| `slot` | a snippet, `children` where there is one |

A prop that is not in `api`, or an `api` entry with no prop, is the divergence the contract exists to catch — declared in the contract, or a defect ([`docs/components/README.md`](../components/README.md), *Exceptions are declared*). What used to be `state = hover/active/focus` and `is focused` is not in `api` after the registry work, so it is not a prop: `:hover`, `:active`, `:focus-visible` and `disabled`/`readonly` carry it in CSS and the DOM.

## 4. Generators

Read the registry, write into `packages/ui/src`, run in `prebuild` after `tokens:css`. Generated files are gitignored and rebuilt, like every other generated thing.

- **`tools/build-ui-types.mjs`** — `props.ts` per component from its `api`: a `type` with a field per property, variant values as a string union, so a wrong value is a compile error and the 1:1 mapping is checked by the compiler rather than by eye. This is the condition under which TypeScript was accepted — types are generated, never hand-written.
- **`tools/build-ui-stories.mjs`** — one Storybook story per component with a case per documented variant, from `api` and `sizing_model`. The "build the core set" gate is met when every generated story renders.
- Both live in `tools/`, are covered by `tools/**/*.test.mjs`, and follow the restricted-YAML reader already there.

## 5. Registry work, first

Before the package, `api` has to describe web components. Per [ADR 0002](../decisions/0002-frontend-stack.md) this is done **per component, as each contract is opened for implementation** — not in one sweep — so a component's `api` is corrected in the same session its `.svelte` is written.

- A property that only draws a state the component decides for itself — `state = hover/active/focus`, `is focused` — moves out of `api` into `figma_notes` as drawing-only, the exception [`registry/README.md`](../components/registry/README.md) already defines for `has scrollbar`. `disabled` and `read only` stay: they are real states.
- [`STANDARD.md`](../components/STANDARD.md) *Complete enough to publish* changes from "every property in Figma appears in `api`" to "…appears in `api`, or in `figma_notes` as drawing-only".
- `npm run validate:registry` gains a check: `state` carrying `hover`/`active`/`focus`, or an `is focused` property, inside `api` is a report — the drawing-only class belongs in `figma_notes`.
- [`naming.md`](../foundations/naming.md) §4: `read only` is added to `state`; `focus` stays (it is not deleted, per Artur 2026-09-06); `active / focus` on Input Text and Select is a component-backlog item, not resolved here.

The `html`/`figma_notes`/`motion` fields being invisible to the loader, validator and page is a separate defect fixed in Stage 0 ([the review's step 0](../../README.md)), not here.

## 6. Tests, lint, a11y

Into CI ([SPEC 0008](0008-development-and-release-flow.md) §4) when the package lands:

- **Vitest 5 browser mode** with `vitest-browser-svelte` for component rendering; jsdom for logic in `src/behaviors`.
- **Playwright** for keyboard behaviour per pattern — focus order, arrow keys, Escape, focus return ([`accessibility.md`](../foundations/accessibility.md)).
- **axe** on every story, `wcag2a`/`wcag2aa`/`wcag22aa` gating and `wcag2aaa` reported ([`accessibility.md`](../foundations/accessibility.md)).
- **Stylelint 17** with `stylelint-config-html` (parses `.svelte`), `color-no-hex`, `unit-disallowed-list: [px]` outside `tokens.css`, and `stylelint-declaration-strict-value` requiring colour, spacing and size to be `var()`.

## 7. Vertical slices

Contract-before-its-component ([ADR 0002](../decisions/0002-frontend-stack.md), [`PLAN.md`](../../PLAN.md)). Each slice corrects its components' `api` (§5), then builds them.

1. **Badge** — static primitive: token → `tokens.css` → `badge.css` → `Badge.svelte` → every variant in a story → the generated `props.ts` matches `api`. Proves the whole chain with no behaviour.
2. **Checkbox Input** — first native interactive: `mixed`, the accessible name, `:focus-visible` in place of `is focused`. Proves the mapping rule against a real control.
3. **Tooltip** — first Zag machine: behaviour, `@supports`-gated anchor positioning, the a11y checks that decide whether Zag holds.
4. **Modal / Drawer** — `<dialog>`: platform behaviour, not a machine.
5. **Dropdown** — the listbox/menu machine, once its ARIA model is settled (component backlog).
6. **Select** — native `<select>`, closed part styled.
7. **The table**, then **Button ×6**.

After slices 1–2 the S5 estimate is tested against real pace, as [`stylos-estimating`] set out — the first time the 11–13-week number meets a line of the package.

## 8. Acceptance

- `@stylos/ui` builds; every documented variant of the core set renders in Storybook from `tokens.css` alone, no hardcoded value.
- Every component's props are exactly its entry's `api` under the §3 rule; a divergence is declared in the contract or fails a check.
- `props.ts` and the stories are generated from the registry, not authored.
- Stylelint rejects a hex or raw `px` outside `tokens.css`; axe gates AA on every story; keyboard tests pass per pattern.
- The CI of [SPEC 0008](0008-development-and-release-flow.md) runs the package's build, tests and lint.
