# docs/decisions/

Decision records for architectural choices — the "why," not just the "what." Per master doc [§23.2](../master-document.md#232-change-process), a material change should record: the problem, affected areas, alternatives considered, the decision and rationale, migration impact, release classification, and follow-up work. Small corrective edits don't need a record — they go straight into the relevant document and `CHANGELOG.md`. Architectural changes do.

Filename pattern: `NNNN-short-title.md`, numbered sequentially, never renumbered or reused.
